The steps below reproduce setup for a **new project**. Do not recreate the current project or overwrite its `.env.local`.

1. [Create a project in Callback HackGT](https://supabase.com/dashboard/new/nfnipvbtabmhycrksvym). Use the Free plan, Americas region, and Data API enabled. Enter/generate a strong database password, save it privately, and click **Create new project**. This password is separate from the demo users' passwords.
2. Once the project is ready, open its SQL Editor. Paste and run the entire [`supabase/schema.sql`](../supabase/schema.sql). It creates the base tables, row-level policies, private photo bucket, and Realtime configuration. Rerun it after pulls that change the schema; for an existing project, apply migrations needed by features you choose to enable. Personal app/SMS compose sharing requires no SMS delivery migration. Presence has no cross-user read policy: raw coordinates are inspected only by the trusted scan service and are returned only as coarse proximity bands. Nearby visibility expires after ten minutes; physical deletion of expired rows needs cleanup.
   **Optional glasses voice messaging:** keep server-only `GLASSES_MESSAGING_ENABLED` unset or `false` for the chosen phone demo. Before enabling it in a target environment, apply [`supabase/migrations/20260926_glasses_voice_messages.sql`](../supabase/migrations/20260926_glasses_voice_messages.sql). The migration scopes reply events to the glasses token that created the scan and permits multiple replies per scan. Then validate the native Android/iOS integration, actual glasses and paired-phone session, and the explicit spoken edit/cancel/confirm flow. Only after those checks set `GLASSES_MESSAGING_ENABLED=true` on the server and redeploy. This setup guide does not claim that migration or hardware validation has been completed for production.
3. Fill these in `callback/.env.local` (the local file is ignored by Git):
   - `NEXT_PUBLIC_SUPABASE_URL`: the project's API URL.
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`: the publishable API key (legacy anon key also works).
   - `SUPABASE_SERVICE_ROLE_KEY`: the server-only service-role key from the project's API keys. Never prefix this with `NEXT_PUBLIC_`.
   - `DEMO_SCANNER_EMAIL` / `DEMO_SCANNER_PASSWORD`: the first demo account, e.g. `alex@example.com` and a new password.
   - `DEMO_RECIPIENT_EMAIL` / `DEMO_RECIPIENT_PASSWORD`: a different account, e.g. `recipient@example.com` and a different password.
   - Optional `DEMO_ADVISOR_EMAIL` / `DEMO_ADVISOR_PASSWORD`: a third account for developer advice-flow testing. The chosen two-person demo does not need this role.
4. From the `callback` folder, run `npm run demo:setup`. This creates confirmed demo accounts without sending invitations, imports the clearly labeled synthetic stories, and maps contacts. Do not create the demo accounts manually first unless you already know their passwords.
5. Copy the printed `DEMO_OWNER_ID` into `.env.local`, set `DEMO_MODE=true`, and set `COMMERCE_ENABLED=true` if testing shopping. For the verified Meta model split, set `MODEL_PROVIDER=meta`, `META_MODEL=muse-spark-1.3` for memory, `META_VISION_MODEL=muse-spark-1.1` for camera recognition, private `MODEL_API_KEY`, and `MODEL_MAX_COMPLETION_TOKENS=6000`. OpenAI remains an explicitly selected fallback only. Stripe is optional for discovery/advice, required for payment. Leave `GLASSES_MESSAGING_ENABLED` unset or `false` for phone rehearsal.
6. Run `npm run dev`. In another terminal run `npm run smoke`, then `npm run access:check`. Smoke exit code **2** means the database is ready but the selected model is unavailable; **1** means a setup failure. The access check uses explicitly labeled developer fixtures, verifies real logins, isolation, photo sharing, send → reply → follow-up, and removes its test data.
7. Sign in at `/login` with the scanner account; use a separate browser profile/device for the recipient at `/inbox`. A real scan needs the selected provider's key. Do not mistake the access-check fixture for model output.

8. For phones, deploy this branch over HTTPS. Set the same environment variables on the host and set `APP_ORIGIN` to the deployed HTTPS address so payment returns to the right site. Restart/redeploy after changing environment variables.

Historical OpenAI checks used a Wingspan manufacturer image and scripted replies: one localhost loop passed 8/8, then five hosted loops passed 51/51 and cancellation/reset passed 14/14. The selected M1/V3 build now uses Meta muse-spark-1.1 vision and muse-spark-1.3 memory; see [READINESS_REVIEW.md](READINESS_REVIEW.md) for current hosted checks and remaining phone gates. ## Personal messaging

See [PERSONAL_MESSAGING.md](PERSONAL_MESSAGING.md). The native share sheet needs no provider setup or recipient Callback account. For an addressed SMS composer, configure the private nested SMS_RECIPIENTS_JSON map by scanner account UUID, then person ID. Flat global person maps are rejected. The current addressed compose path also checks the linked recipient account; otherwise use the personal-app chooser. Do not put phone numbers in Git.

Callback has no server-originated SMS route or provider integration. Native sharing opens the user's messaging app; Callback does not confirm that a text was sent or delivered. No migration is needed for native sharing.
